# 0009 TUI and the manager's overview

Status: accepted. First written 2026-10-10 (spike DIPO-6). Rewritten 2026-10-24 for the simplified design. The research behind the rewrite is in `docs/research/2026-10-24-simplification-audit.md`.

## Decision in short

The TUI is the first client. It is built with Ink 8 and React and is a thin client: it shows views the engine derived, and it acts only through commands (0005). For one office at a time it answers four questions: who works on what, how it is going, what needs the maintainer, and what it costs. The plain-text commands `dipo desk` and `dipo watch` read the same views.

## 1. A thin client

- **Only the contract.** The TUI imports only `contract` and `client` (0004). It reads `engine.hello`, subscribes to the software stream, reads `office.snapshot` for the chosen office and subscribes after its cursor (0005).
- **The store.** Its state is the `OfficeStore` from `client`. The store takes the snapshot, applies events by subject, drops duplicates by seq and handles a reset. It replaces views and never computes a column, health, phase or cost.
- **Keys from the engine.** Keys come from `commands.describe` and the actions the engine attaches to each desk item and park.
- **No model.** The overview, desk, digest and cost views are built by engine code from facts.
- **One store for every client.** A later web client uses the same store, so the two cannot disagree.

## 2. The vocabulary

One word per meaning, and every one is engine-derived.

- **Phase:** `setup` (claim and box), `build`, `review`, `test` (waiting for the maintainer's test), `merge`.
- **Health of a running session.** The engine derives it in this order; each state shows as a word plus a glyph:

  | Health | When |
  |---|---|
  | `lost` | The worker host died, or its exit is not processed yet (the story parks next) |
  | `looping` | The same failure signature twice in a row, or the last allowed loop |
  | `stuck` | No output for `timeouts.workerStallMinutes` (default 20) |
  | `quiet` | No output for `timeouts.workerQuietMinutes` (default 3) |
  | `busy` | Output within the quiet window |

  The watchdog facts behind it (`no-output`, `same-failure`, `host-lost`) reach the client as the evidence of a `work.observed` event. They are not a second vocabulary.
- **Lifecycle** is 0012's.
- **Queue column:** `draft`, `refined`, `ready`, `waiting` (Ready, but a dependency is not Done), `running`, `review`, `desk`, `done`.
- **Evidence labels.** Each value the engine sends carries one: `checked` (the engine measured it), `claimed` (the worker or reviewer said so), `estimated` (computed by a rule) or `none` (no fact; shown as `?`, never guessed). A claimed value shows a trailing `*`, an estimated one a leading `~`.
- **Your desk** is everything that waits on the maintainer (0020).

## 3. Views

Views are numbered `1` to `4`. `o` opens the office switcher, and `Enter` drills in.

- **Office switcher** (`o`). One row per office: running, needs you, Ready, today's tokens, and a spend alert when one is on.
- **Overview** (`1`, home). A count line (running, needs you, in review, Ready, waiting, today's tokens), then the sections RUNNING, NEEDS YOU, IN REVIEW and READY, with each story's title. A running row shows phase, health, criteria, loop, budget share, time and a `now:` line with the newest worker line and its age. A "since you left" line comes from `office.digest`. The TUI passes the time it last saw the office, kept locally.
- **Queue** (`2`). One section per column. A Refined row shows its first Ready gate failure with the rule id.
- **Story detail** (`Enter`). Facts on the left. On the right, the worker output from `work.output` and `work.outputRange`, or the stored prompt (`i`). An ended run is shown read-only.
- **Desk** (`3`). The `office.desk` read, in its order, with each item's actions bound to keys.
- **Test checklist** (`4`, or `t` on a desk item). `test.start` returns the test box's URL and the manual steps. Ticks are local UI state, and the outcome is one `test.record`.

A cost view by story, role and tier is Later.

## 4. Actions

Every action is one command (0005) with `origin: "tui"` and a fresh request id. The TUI asks for confirmation where `commands.describe` says `confirm`, and for the typed story id where it says `irreversible` (`work.discard`, and `story.drop` with `--delete-branch`).

| Key | Command |
|---|---|
| `a` | `work.answer` |
| `s` | `work.steer` |
| `r` | `work.resume` |
| `P` | `story.park` (asks for a note) |
| `Shift-D` | `work.discard` (typed) |
| `d` | `story.drop` |
| `y` / `n` | `gate.approve` / `gate.reject` (a reject needs a note); on a proposal row, `proposal.accept` / `proposal.dismiss` |
| `t`, then pass or fail | `test.start`, then `test.record` (a fail needs a note) |
| `u` in the queue | `work.run` |
| `S` in the banner | `daemon.resumeScheduling` |
| `F` in the switcher | `office.forget` |

- **Errors** show in the footer. A retryable error offers a retry with the same request id. `changed: false` shows "already so".
- **Read-your-writes.** After a reply the TUI waits until its stream passes the reply's cursor before it marks the action done.

**Global keys:** `1` to `4`, `o`, `Tab`, `j` and `k` or the arrows, `Enter`, `Esc`, `/` to filter, `:` for a palette of every command, `e` for evidence words, `?` for help, and `q` to quit. Uppercase keys end or replace work. No action fires without its target visible on screen.

## 5. Connection and daemon states

- **Start.** `dipo tui` starts the daemon if needed and opens the office of the current directory or the last one used.
- **Offline.** The header shows `OFFLINE since <time>` and values keep their age. Action keys are disabled and typed text is kept. The client reconnects with backoff (0.5 s, doubling to 5 s) and subscribes after its last cursor.
- **A reset.** On `stream.resetRequired` the store reloads and says so once.
- **The banner.** It shows `recovering`, `draining` and an office's starts paused (0020) with the reason and what lifts it. A version mismatch suggests `dipo daemon restart`.

## 6. Spend alerts

Spend alerts count all offices together, per UTC day and UTC month, against the limits in `<state>/config.yaml`. They count tokens as the budget counts them (0008). The cost the CLI reports is shown next to them, never alerted on. An alert shows in the switcher, the overview count line, the `dipo watch` header and the `dipo desk` count line, and once as an `engine.notice` per window and level.

## 7. Terminals and accessibility

- **Width.** At 120 columns everything shows. From 80 to 119 the wide columns drop. From 60 to 79 each running story is a two-line card. Below 60 columns or 16 rows, one short list shows. There is never horizontal scrolling.
- **Screen.** The alternate screen is the default, and `--inline` renders in the scrollback. `dipo desk` and `dipo watch` are plain text and never use Ink.
- **No colour-only signals.** Every state is a word plus an ASCII glyph. `NO_COLOR`, `--no-color` and `--ascii` are honoured. Tests assert on frames with ANSI stripped.
- **Performance.** The store batches events at most 10 times a second. Output panes keep only the visible lines and fetch the rest.

## Replaced

- Eight health states including `asking`, `limited` and `paused`, and seven watchdog signals as a public vocabulary (2026-10-10). Replaced by five health states with the signals as evidence (2026-10-24). A question parks, a plan limit pauses the office, and pause is gone (0020).
- The phase `verify` (2026-10-10). The worker runs verify inside `build`, and CI is the verify (0002).
- The `held` column and "Held by you". Replaced by "Parked by you" on the desk (0020).
- Keys for pause, reassign, stop, hold, and allow or deny of permissions (2026-10-10). Replaced by park (0020) or removed.
- The digest counted from the last TUI disconnect, stored by the engine (2026-10-22). Replaced by a `since` the TUI keeps itself (2026-10-24), so the engine does not depend on which clients connect (0001).
- The `safe` banner and `contract.unsupported` handling. Replaced by 0005's states and its single version.
- The Ink prototype gate (2026-10-10). Passed: the TUI ships on Ink 8 inside the compiled binary.
- A web, desktop or 3D client through a loopback listener (2026-10-10). Later (0003).
- The cost view `5` and `office.usage` (2026-10-10). Later; `office.usage` was never built.
