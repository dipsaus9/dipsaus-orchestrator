## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Outcome: `dipo drop <id> --delete-branch` shows the commits not on the base and the uncommitted and untracked files it removes before it asks for the typed story id; a release that fails after the story PR was closed says the PR was closed; and --delete-branch deletes the kept branch of an unclaimed story, as its text promises.

Context: review of DIPO-160 (PR #251). 0020 section 8: story.drop with deleteBranch removes a dirty worktree with --force, so clients ask for the typed story id after listing the commits not on the base and the uncommitted and untracked files; with --delete-branch the branch is deleted locally and remotely. dropCommand in packages/cli/src/story-commands.ts asks with a fixed warning, and the test in story-commands.test.ts checks "cannot be undone" and "Type DIPO-7". No read gives the lists: story.detail (packages/contract/src/office.ts) holds the view, the active run, runs, verdicts and questions; dirtyFilesOf in packages/engine/src/worktree/release.ts lists the files; nothing lists the commits. drop in packages/engine/src/stories/planning.ts closes the PR (#closePr commits its closed state) before #release, and a failed release throws "<story> was not dropped: <why>" and withdraws the journal entry while the PR stays closed. Without a live claim drop skips #release, so deleteBranch deletes nothing, while the CLI prints "its worktree and branch are removed"; a branch kept by an earlier release stays open in released_branches (packages/engine/src/worktree/records.ts; releasedBranchFor reads one by key and branch). The maintainer chose a new office read, story.losses, on 2026-10-20; `dipo discard` (DIPO-161, work.discard, still provisional) reads the same list and depends on this story. This story depends on DIPO-227: both change drop() in packages/engine/src/stories/planning.ts, its tests, packages/daemon/src/foreground.ts and packages/contract/src/office.ts. Office reads are defined in packages/contract/src/office.ts (officeReads), have a fixture in packages/contract/src/fixtures.ts, are listed with their since in packages/contract/src/work.test.ts, and packages/contract/schema/ is generated by `bun run contract:schema` and pinned by packages/contract/scripts/schema.test.ts. StoryPlanning's feature (packages/engine/src/stories/planning.ts), registered by packages/daemon/src/foreground.ts, holds the office git the read needs; story.gate is an async read registered the same way (packages/engine/src/gate/store/feature.ts).

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Before the typed id, `dipo drop <id> --delete-branch` prints the commits on the story's branch that are not on the base (short sha and subject, at most 20 and a count of the rest) and the uncommitted and untracked files of its worktree (at most 50 and a count of the rest), read through the office read story.losses; with neither it says that no commits or files are lost, and when the read fails it prints why and drops nothing
- [x] #2 The engine answers story.losses as an async office read registered in StoryPlanning's feature (packages/engine/src/stories/planning.ts): it lists the commits in the office's git queue against the base as last fetched and the files as dirtyFilesOf does, for a live claim and for an open released_branches branch of the story, returns empty lists for a story with neither, and changes nothing
- [x] #3 The contract defines the office read story.losses { office, story } in packages/contract/src/office.ts, since 1 and listed in officeReads, whose result holds the story, its key, the commits (short sha and subject) and the files; packages/contract/src/fixtures.ts has its fixture, packages/contract/src/work.test.ts lists it among the reads shipped in minor 1, and packages/contract/schema/ equals a fresh `bun run contract:schema`
- [x] #4 When a drop's release fails after the drop closed the story PR, the error says that PR #<n> was closed and the story was not archived, with the release's reason
- [x] #5 story.drop with deleteBranch and no live claim deletes, locally and on the remote, each branch with an open released_branches row for the story's key, and sets reclaimed_at on those rows so no later claim reuses a deleted branch
- [x] #6 Tests in packages/cli/src/story-commands.test.ts show the lists before the typed-id question, the empty case and a failed read dropping nothing, with the existing checks for "cannot be undone" and "Type DIPO-7" kept; tests in packages/engine/test/backlog/planning.test.ts and planning.ci.test.ts cover criteria 2, 4 and 5, the ci test with a real repository and a bare remote
