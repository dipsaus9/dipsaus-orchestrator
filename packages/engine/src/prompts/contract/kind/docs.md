## What to deliver

Markdown documents that meet every criterion, written only in the area the `<area>` section of the task message names. dipo handles git, the backlog, the pull request and the review, and you report to dipo instead: the box's git repository is your own. dipo checks each part against your area and does not run the verify at done. A review finding comes back to you as feedback. Hand a part after each criterion you meet. Do not change the story's task file: dipo refuses a part that does.
